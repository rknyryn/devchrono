# v3.0 — Pomodoro Timer Feature

> **Status:** Architecture approved — ready for implementation  
> **Approved by:** Cooper (Lead) + TARS (Architect)  
> **Session date:** 2026-04-28

---

## Feature Overview

Add an opt-in Pomodoro timer to DevChrono. When active, it tracks work/break phases and displays a full-editor-area break panel when rest time arrives. The user can skip the break early via a button.

**Key constraint:** VS Code extensions cannot truly block user input. The break panel is a *visual focus aid*, not a hard lock. A persistent WebviewPanel that auto-reopens on dismiss is the maximum achievable enforcement within the VS Code API sandbox.

---

## Architecture Decisions

### 1. Module Boundaries

- **New module:** `src/pomodoroManager.ts` — owns the Pomodoro state machine
- **New module:** `src/views/pomodoroBreakPanel.ts` — owns the break WebviewPanel
- **`sessionManager.ts` is untouched.** `pomodoroManager` is a *consumer* of sessionManager, not a peer.
- **`extension.ts`** wires them together (imports both, passes callbacks)

Dependency direction:
```
extension.ts
  → pomodoroManager.ts  (calls startPomodoro / stopPomodoro)
  → pomodoroBreakPanel.ts (called by pomodoroManager on phase change)
  
pomodoroManager.ts
  → sessionManager.ts   (calls startSession / endSession)
  → pomodoroBreakPanel.ts (shows/hides panel)
  
sessionManager.ts       (no changes — no imports from pomodoroManager)
```

### 2. Pomodoro Phase = DevChrono Session

A Pomodoro **work phase** maps to a normal DevChrono session:
- Phase starts → `startSession()` is called
- Phase ends (break begins) → `endSession()` is called
- Break ends → `startSession()` again for next phase

**No schema changes.** Pomodoro work sessions appear in `time-log.json` as regular sessions. Break phases have no session — this is correct. `schemaVersion` stays at current value.

Future (v3.1): add `"source": "pomodoro"` tag to session data if Pomodoro-specific analytics are needed.

### 3. Timer Architecture

Two clocks with clear ownership:

| Clock | Location | Responsibility |
|-------|----------|----------------|
| **Authoritative timer** | Extension host (`setInterval` + `Date.now()` deltas) | Phase transitions, persists across webview teardowns, drift-safe |
| **Display countdown** | Webview JS (`setInterval`) | Smooth per-second UI rendering only |

The host timer uses wall-clock delta arithmetic (`Date.now() - phaseStartTime`) — not tick counting — so system sleep/suspend doesn't corrupt the state.

**Sync protocol (extension host ↔ webview):**
```typescript
// Host → Webview
{ type: 'pomodoroState', phase: 'break'|'work', remainingSeconds: number, totalSeconds: number }

// Webview → Host  
{ type: 'skipBreak' }
{ type: 'ready' }   // webview signals it's loaded and can receive messages
```

The host sends state on: phase transition, webview `ready` signal, and as a correction every 30 seconds (handles drift).

## Data Model

```typescript
type PomodoroPhase = 'idle' | 'work' | 'break';

interface PomodoroState {
  phase: PomodoroPhase;
  phaseStartTime: string;        // ISO 8601 wall-clock anchor
  workDurationSeconds: number;   // from config, default 1500 (25 min)
  breakDurationSeconds: number;  // from config, default 300 (5 min)
}
```

Pomodoro state is **ephemeral** — in-memory only. It does not survive VS Code restarts (correct behavior — if VS Code closes mid-break, break is abandoned).

## Break Panel (`pomodoroBreakPanel.ts`)

Template: mirrors `src/views/summaryPanel.ts` structure.

- `ViewColumn.One` — takes over the main editor column
- `retainContextWhenHidden: true` — webview timer survives re-hide
- **Persistent panel pattern:**
  - `onDidDispose` → immediately recreate the panel
  - `onDidChangeViewState` (visible=false) → call `panel.reveal()`
  - This creates ~1s "rubber band" effect — not atomic, a motivated user can escape, but it provides strong visual friction
- `onDidReceiveMessage({ type: 'skipBreak' })` → calls `pomodoroManager.skipBreak()`

Break panel shows:
- Break duration countdown (from webview JS, corrected by host every 30s)
- Prominent "Skip Break / Continue Working" button

## New Commands

| Command ID | Title | Behavior |
|---|---|---|
| `devchrono.startPomodoro` | DevChrono: Start Pomodoro | Starts first work phase; starts session tracking |
| `devchrono.stopPomodoro` | DevChrono: Stop Pomodoro | Cancels Pomodoro; ends active session; returns to passive tracking |
| `devchrono.skipBreak` | DevChrono: Skip Break | Ends break early; dismisses panel; starts next work phase |

## Status Bar Updates

When Pomodoro is active, status bar display changes:

| Phase | Display |
|-------|---------|
| Work phase | `🍅 Pomodoro: 18:32 \| ⏱ Toplam: 2s 14dk` |
| Break phase | `☕ Mola: 4:11` |
| Pomodoro off | Existing behavior unchanged |

`pomodoroManager` exposes a `getPomodoroState()` getter. `updateStatusBar()` in `sessionManager.ts` queries it. 

**Note:** `updateStatusBar()` needs a refactor before this is added — Brand should extract a `formatStatusBarText()` pure function to keep complexity manageable.

## New Configuration Keys (`package.json`)

```json
"devchrono.pomodoro.workMinutes": {
  "type": "number",
  "default": 25,
  "minimum": 1,
  "maximum": 120,
  "description": "Pomodoro work phase duration in minutes."
},
"devchrono.pomodoro.breakMinutes": {
  "type": "number", 
  "default": 5,
  "minimum": 1,
  "maximum": 60,
  "description": "Pomodoro break phase duration in minutes."
},
"devchrono.pomodoro.breakEnforcement": {
  "type": "string",
  "enum": ["soft", "persistent"],
  "default": "persistent",
  "description": "soft: break panel appears but can be dismissed freely. persistent: panel re-opens when dismissed."
}
```

Config changes during an active phase: current phase completes with old values, new values take effect on next phase.

## Session Interaction Matrix

| Scenario | Behavior |
|---|---|
| Pomodoro work phase starts | `startSession()` — normal tracking |
| Pomodoro work phase ends | `endSession()` — break panel appears |
| User skips break | Dismiss panel → `startSession()` for next work phase |
| Break expires naturally | Same as skip |
| `stopPomodoro` during work | `endSession()` → resume passive tracking → `startSession()` |
| `stopPomodoro` during break | Dismiss panel → `startSession()` for passive tracking |
| VS Code closed during work | `deactivate()` → `endSession()` runs normally — orphan recovery unchanged |
| Idle detection during work | Runs unchanged — idle seconds subtracted as usual |

## What We Cannot Do (VS Code API Limits)

| Requirement | Verdict |
|---|---|
| Block keyboard input (Ctrl+Tab, etc.) | ❌ No API exists |
| Prevent terminal / sidebar interaction | ❌ No API exists |
| Show countdown in a blocking native dialog | ❌ Modal dialogs are static text only |
| Programmatically close a modal dialog | ❌ No API exists |
| Full-screen overlay over all VS Code chrome | ❌ Requires OS-level API — violates zero-deps charter |
| Prevent app switching | ❌ OS-level, not possible |

The break panel is a **focus aid, not a hard lock.**

## User Stories & Acceptance Criteria

### User Story 1: Start a Pomodoro Session
**As a developer** wanting to improve focus,  
**I want** to start a 25-minute Pomodoro timer via the command palette,  
**So that** I can track focused work time separately from my background time tracking.

**Acceptance Criteria:**
- [ ] Running `devchrono.startPomodoro` command initiates a work phase timer
- [ ] Status bar updates to show `🍅 Pomodoro: 24:59 \| ⏱ Toplam: ...` with correct countdown
- [ ] A DevChrono session starts (recorded in `time-log.json`)
- [ ] Timer runs for configured work duration (default: 25 min)
- [ ] At end of work phase, the session is persisted and break panel appears automatically

### User Story 2: Take a Break When Timer Expires
**As a developer** who needs to rest between focus intervals,  
**I want** a break timer and visual reminder when my work phase ends,  
**So that** I don't skip my break to maintain focus cycles.

**Acceptance Criteria:**
- [ ] Break panel appears automatically when work phase ends, covering the main editor area
- [ ] Status bar changes to `☕ Mola: 4:59` showing break countdown
- [ ] Break panel displays a large countdown timer and a "Skip Break / Continue Working" button
- [ ] Timer counts down from configured break duration (default: 5 min)
- [ ] If user dismisses the panel manually (`persistent` mode), it re-opens within ~1 second
- [ ] User is not blocked from using terminal, sidebar, or other VS Code UI during break
- [ ] When break expires naturally, panel closes and next work phase begins

### User Story 3: Skip a Break Early
**As a developer** with uninterrupted momentum,  
**I want** to skip my break and go straight to the next work phase,  
**So that** I can continue working when I'm in flow.

**Acceptance Criteria:**
- [ ] "Skip Break" button on break panel dismisses the panel immediately
- [ ] Next work phase (session) starts immediately upon skip
- [ ] Status bar updates to reflect new work phase
- [ ] Session time is logged accurately (break is not tracked as session time)

### User Story 4: Stop Pomodoro and Resume Passive Tracking
**As a developer** who needs to switch contexts,  
**I want** to cancel the Pomodoro timer and return to background time tracking,  
**So that** I can stop the focused timer without losing my overall workspace time.

**Acceptance Criteria:**
- [ ] Running `devchrono.stopPomodoro` cancels the active Pomodoro
- [ ] Current phase (work or break) ends immediately
- [ ] If in work phase, session is ended and persisted
- [ ] Status bar reverts to normal passive tracking display (⏱ Toplam: ...)
- [ ] DevChrono continues tracking time passively as before

### User Story 5: Configure Work and Break Durations
**As a developer** with personal time preferences,  
**I want** to adjust Pomodoro work and break durations in VS Code settings,  
**So that** I can customize the timer to my workflow.

**Acceptance Criteria:**
- [ ] `devchrono.pomodoro.workMinutes` setting accepts 1–120 minutes (default: 25)
- [ ] `devchrono.pomodoro.breakMinutes` setting accepts 1–60 minutes (default: 5)
- [ ] Configuration changes take effect on the **next** Pomodoro cycle (current cycle completes with old values)
- [ ] Invalid values (negative, out-of-range) are rejected by VS Code schema validation
- [ ] Settings are persisted in user's VS Code settings and survive VS Code restart

---

### Out of Scope (v3.0)

The following are explicitly **NOT** included in this release to keep scope lean:

- Pomodoro cycle counter or history ("completed 3 Pomodoros today")
- Automatic long breaks (every 4th cycle)
- Notification sounds or system alerts on phase transitions
- Pomodoro-specific statistics in the summary panel
- Hard keyboard/UI input blocking (architectural limit of VS Code API)
- Mobile/browser-based Pomodoro tracking
- Integration with calendar or scheduling tools
- Tagging sessions as "pomodoro" in the data model (may add in v3.1)
